# OpenEO Authentication Setup Guide

This guide shows you how to set up authentication for accessing Sentinel-2 data through OpenEO, and how the tokens are stored.

## Why Do I Need This?

The `sentinel-fetch` process uses OpenEO Copernicus Data Space backend to fetch and process Sentinel-2 satellite imagery. This requires authentication with a refresh token.

## One-Time Setup

### Step 1: Get a Copernicus Account

If you don't have one already:

1. Go to [dataspace.copernicus.eu](https://dataspace.copernicus.eu/)
2. Click "Register"
3. Create your free account

### Step 2: Run the Token Setup Script

From your project root directory:

```bash
./process-api/scripts/get_openeo_token.sh
```

**What this does:**

1. Shows you a URL to open in your browser
2. You log in with your Copernicus credentials
3. The script extracts your refresh token

The same script serves both storage methods (see [Token Storage](#token-storage) below): the token is written automatically to `refresh-tokens.json`, and the script also prints an `OPENEO_REFRESH_TOKEN=...` line you can copy into `.env`.

### Step 3: Reload pygeoapi

**Important**: `docker compose restart` does NOT reload `.env` variables. You must use:

```bash
docker compose down && docker compose up
```

### Step 4: Test It

```bash
curl -X POST "http://<host>:5000/processes/sentinel-fetch/execution" \
  -H "Content-Type: application/json" \
  -d '{
    "inputs": {
      "farm_id": 75,
      "temporal_extent": ["2024-06-01", "2024-08-31"],
      "output_products": ["ndvi"],
      "aggregation_method": "max",
      "cloud_cover_max": 15
    }
  }'
```

**Done!** You're all set.

## Token Storage

Tokens live in `process-api/config/openeo-config/`:

- `refresh-tokens.json` — refresh tokens for OpenEO authentication (auto-generated by `get_openeo_token.sh`, **DO NOT commit**)

The [openEO](https://open-eo.github.io/openeo-python-client/) Python client library automatically manages refresh tokens: it loads the token from this directory when needed, and the token persists across Docker restarts, container rebuilds, and system reboots via a volume mount.

The location is configured via the `OPENEO_CONFIG_HOME` environment variable in `docker-compose.yml`:

```yaml
environment:
  - OPENEO_CONFIG_HOME=/app/config/openeo-config
volumes:
  - ./process-api/config/openeo-config:/app/config/openeo-config
```

## Authentication Priority

The process-api service authenticates with openEO in this order:

1. **`OPENEO_REFRESH_TOKEN` environment variable** (primary - recommended for production)
2. **`$OPENEO_CONFIG_HOME/refresh-tokens.json`** (fallback - for local development)

### Primary: Environment Variable (Recommended)

Set the `OPENEO_REFRESH_TOKEN` in your `.env` file:

```bash
# In .env file
OPENEO_REFRESH_TOKEN=your_refresh_token_value_here
```

To obtain the token:

1. Run `./process-api/scripts/get_openeo_token.sh`
2. Copy the `OPENEO_REFRESH_TOKEN=...` line from the script output
3. Paste it into your `.env` file

### Fallback: JSON Config File (Local Development)

The system falls back to the JSON config file if `OPENEO_REFRESH_TOKEN` is not set or contains the placeholder value. Running the setup script writes the token to this file automatically — no manual copy-paste needed.

The openEO client looks for tokens in:

1. `$OPENEO_CONFIG_HOME/refresh-tokens.json` (the mounted config directory)
2. `~/.local/share/openeo-python-client/refresh-tokens.json` (Linux default)
3. `%APPDATA%/openeo-python-client/refresh-tokens.json` (Windows default)

This fallback is useful for local development without modifying `.env`, and for quick testing after running the setup script.

## Security Notes

- **NEVER** commit `refresh-tokens.json` to version control
- The `.gitignore` file excludes this file by default
- If compromised, re-run the setup script to obtain a new token

## How Often Do I Need to Do This?

**Once!** You only need to refresh the token if:

- The token expires (~30 days typically, but can be longer)
- Authentication fails and the token is not found in any of the fallback locations (see [Authentication Priority](#authentication-priority))

## Troubleshooting

### Error: "Failed to retrieve access token... invalid_grant"

- Your refresh token expired (tokens last ~30 days)
- Run the setup script again to get a new token

### Script hangs after entering URL

- Make sure you actually opened the URL in your browser
- Make sure you completed the login process
- Check that you returned to the terminal

### "Permission denied" when running script

```bash
chmod +x process-api/scripts/get_openeo_token.sh
./process-api/scripts/get_openeo_token.sh
```

### Authentication fails with a token in place

1. Check that `refresh-tokens.json` exists in `process-api/config/openeo-config/`
2. Verify file permissions allow read access
3. Re-run `./process-api/scripts/get_openeo_token.sh` to obtain a fresh token
4. Check Docker volume mounts in `docker-compose.yml`
